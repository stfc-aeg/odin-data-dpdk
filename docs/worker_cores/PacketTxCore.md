## Overview

The PacketTxCore is the DPDK transmit stage for packets generated by the PacketGeneratorCore. It connects to the upstream TX rings created for each NIC port, dequeues queued `rte_mbuf` objects, and forwards them to the physical Ethernet device using `rte_eth_tx_burst()`.

## Configuration

The PacketTxCore accepts the following configuration block:

```json
"packet_tx": {
    "core_name": "PacketTxCore",
    "num_cores": 1,
    "stream": "primary",
    "mode": "test_16bit",
    "connect": "packet_generator",
    "num_devices": 3,
    "destination_port": 1234
}
```

### Configuration Parameters

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `core_name` | string | Name of the class for this core type |
| `num_cores` | integer | Number of PacketTxCore instances to create |
| `connect` | string | Name of the upstream core whose TX rings should be consumed |
| `upstream_core` | string | Name used to look up the upstream packet-generation ring |
| `num_downstream_cores` | integer | Number of downstream worker cores this transmit stage is expected to serve |
| `num_devices` | integer | Number of transmit devices expected to be attached |
| `destination_port` | integer | Destination UDP port used by the upstream traffic path |

## Connections

### Upstream Connections

- **Packet Generator Ring** (`upstream_ring_`): Looks up the ring created by the upstream PacketGeneratorCore using `ring_name_str(config_.upstream_core, socket_id_, proc_idx_)`.
- **Shared Buffer Ring** (`clear_frames_ring_`): Connects to the shared hugepages recycler so the TX stage can participate in the same buffer lifecycle as the packet-generation path.
- **Per-Port TX Rings** (`tx_port_<port_id>`): Each valid DPDK port exposes a ring that is populated by the generator and drained by the TX core.

### Downstream Connections

- **NIC TX Burst**: Calls `rte_eth_tx_burst(tx_dev.port_id, 0, &mbuf, 1)` for each dequeued packet, handing the packet to the underlying Ethernet device.
- **Packet Release on Failure**: If a transmit attempt fails, the mbuf is freed immediately to avoid leaking queued packets.

## Runtime Configuration

The PacketTxCore does not implement a large runtime configuration surface. Its public command list is empty, so there are no active runtime `start`/`stop` commands beyond the core lifecycle itself.

## Processing Loop

The core runs a lightweight polling loop in `run()`:

1. **Ring Polling**: Iterates through each connected TX device and attempts to dequeue a `rte_mbuf` with `rte_ring_dequeue()`.
2. **Transmission**: Calls `rte_eth_tx_burst()` to hand the packet to the NIC queue for the selected port.
3. **Failure Handling**: If no packet is transmitted, logs the port failure and frees the mbuf.
4. **Idle Delay**: Calls `rte_pause()` when no packets are waiting to avoid a hot spin loop.
